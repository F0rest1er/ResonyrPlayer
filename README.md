# Resonyr

Быстрый и легкий self-hosted музыкальный сервер на Go и PostgreSQL.

Работает в браузере и как PWA на телефоне, умеет играть треки офлайн, подключать облачные диски и управлять воспроизведением между устройствами.

## Документация

- [Руководство пользователя](USAGE.md) — как пользоваться плеером, горячие клавиши, плейлисты и офлайн-режим.
- [Подключение облаков](CLOUDS.md) — пошаговая настройка Google Drive, Яндекс Диска, Dropbox и OneDrive.
- [Создание тем](THEMES.md) — как сделать и загрузить свою тему оформления.

## Что умеет

- Проигрывание всех популярных форматов: MP3, FLAC, AAC, M4A, OGG, OPUS, WAV.
- Полноценный PWA-клиент с офлайн-режимом: скачивайте треки или плейлисты целиком и слушайте без интернета.
- Встроенный файловый менеджер: загрузка отдельных файлов или целых папок прямо через браузер.
- Удаленное управление: переключайте треки на компьютере с телефона или наоборот (аналог Spotify Connect).
- Подключение облачных хранилищ: Google Drive, Яндекс Диск, Dropbox, OneDrive.
- Редактирование тегов и обложек треков прямо в интерфейсе без изменения оригинальных файлов.
- Отслеживание свежих релизов любимых исполнителей через MusicBrainz.
- Настраиваемые темы оформления (светлая, темная, системная и пользовательские ZIP-темы).
- Многопользовательский режим с разграничением прав (администраторы и пользователи).
- Автоматические резервные копии базы данных.

## Быстрый старт

Для запуска нужен сервер на Linux (Ubuntu, Debian, Fedora или Alpine) с установленным `curl`.

### Установка одной командой

Скрипт сам установит Docker, Docker Compose, Git и OpenSSL, создаст файл конфигурации с надежными случайными паролями и запустит сервер.

**Вариант 1. Установка по IP (без домена):**

Перед запуском откройте порт `8080/tcp` в фаерволе.

```bash
curl -fsSL https://raw.githubusercontent.com/F0rest1er/ResonyrPlayer/main/install-remote.sh | sh
```

**Вариант 2. Установка с доменом (автоматический HTTPS):**

Направьте A/AAAA-запись вашего домена на IP сервера и откройте порты `80/tcp`, `443/tcp` и `443/udp`. Caddy автоматически выпустит и продлит бесплатный SSL-сертификат Let's Encrypt.

```bash
curl -fsSL https://raw.githubusercontent.com/F0rest1er/ResonyrPlayer/main/install-remote.sh | sh -s -- music.example.com
```

### Ручная установка через Git

Если вы предпочитаете клонировать репозиторий вручную:

```bash
git clone https://github.com/F0rest1er/ResonyrPlayer.git ~/player
cd ~/player

# Запуск по IP:
./install.sh

# Или запуск с доменом:
DOMAIN=music.example.com ./install.sh
```

## Настройка фаервола

Откройте нужные порты в зависимости от выбранного режима.

### Ubuntu / Debian (UFW)

```bash
# Не забудьте разрешить SSH
sudo ufw allow OpenSSH

# Для работы по IP:
sudo ufw allow 8080/tcp

# Для работы по домену:
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 443/udp

sudo ufw enable
```

### Fedora (firewalld)

```bash
# Для работы по IP:
sudo firewall-cmd --permanent --add-port=8080/tcp

# Для работы по домену:
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --permanent --add-port=443/udp

sudo firewall-cmd --reload
```

## Первый вход

После завершения установки в терминале появятся адрес сервера, логин `admin` и временный пароль:

1. Откройте полученный адрес в браузере (`http://IP_СЕРВЕРА:8080` или `https://music.example.com`).
2. Войдите с логином `admin` и паролем из терминала.
3. Нажмите на имя пользователя в правом верхнем углу и смените логин и пароль на свои.

## Как добавить музыку

Есть три простых способа:

1. **Через браузер**: откройте раздел «Медиатека» и нажмите кнопку «↑ Музыка», либо перейдите в раздел «Файлы» и просто перетащите файлы или целую папку с музыкой в окно браузера.
2. **Напрямую на сервере**: скопируйте аудиофайлы в папку `~/player/music` и нажмите кнопку «Сканировать» в левом меню.
3. **Из облака**: перейдите в «Источники», подключите Google Drive, Яндекс Диск, Dropbox или OneDrive по [инструкции](CLOUDS.md) и нажмите «Синхронизировать».

## Обновление

### Из веб-интерфейса

Администратор может установить опубликованный релиз в разделе «Система» → «Установить обновление». Перед установкой создаётся резервная копия базы, затем плеер пересобирается и перезапускается. Музыка и `.env` сохраняются. Во время перезапуска сайт и воспроизведение будут недоступны. Автоматического отката базы нет; при ошибке смотрите журнал процесса обновления.

Для существующей установки один раз установите код с этой функцией обычным способом и запустите на хосте из папки проекта:

```bash
sh web-updater.sh
```

Процесс должен работать постоянно. Для проверки оставьте терминал открытым. Для фонового запуска на macOS или Linux:

```bash
nohup sh web-updater.sh > web-updater.log 2>&1 &
```

После перезагрузки хоста запустите процесс снова или настройте его через менеджер служб ОС. Не запускайте два экземпляра. Docker должен быть запущен, а у владельца процесса должен быть доступ к Docker и рабочей копии Git. Сам веб-контейнер доступа к Docker не получает: он оставляет запрос в своём томе данных.

В `.env` укажите `UPDATE_REPOSITORY=F0rest1er/ResonyrPlayer`. Git remote `origin` этой рабочей копии должен указывать на тот же репозиторий. Опубликуйте обычный GitHub Release с новым тегом вида `v1.2.3`: простой push в `main` не считается релизом. Локальные изменения отслеживаемых файлов блокируют установку, они не сбрасываются. Не используйте для обновлений рабочую копию с незавершённой разработкой.

При обновлении по тегам Git переходит в detached HEAD — это нормально для серверной установки. После аварийного завершения процесса пустая `.web-updater-lock` может остаться в папке проекта; удалять её можно только убедившись, что другой процесс обновления не работает. Незавершённую установку после аварии проверяйте вручную по журналу, не запускайте параллельное обновление.

### Из терминала

Когда на GitHub выходит новая версия, в шапке плеера у администратора появляется уведомление.

Для обновления перейдите в каталог проекта и запустите:

```bash
cd ~/player
./update.sh
```

Скрипт скачает последний релизный тег с GitHub и пересоберет контейнеры. Все пользовательские данные, база и музыка сохраняются.

В мобильном PWA и браузере интерфейс обновится автоматически через Service Worker.

## Резервные копии и перенос

Файлы, загруженные через интерфейс, лежат в `music`. Чтобы перенести и их, запускайте экспорт с `INCLUDE_MUSIC=YES`. Дамп базы из раздела «Система» музыку не содержит.

### После обновления интерфейса

Команды запускайте из папки проекта:

```bash
cd ~/player
docker compose up -d --build app
```

Это пересобирает уже скачанные исходники, но не получает изменения с GitHub. Сначала обновите код по инструкции выше. Затем перезагрузите страницу. Если старый интерфейс остался, закройте все вкладки и ярлык Resonyr и откройте снова. Не очищайте данные сайта без необходимости: вместе с ними пропадут скачанные на устройство песни.

Яндекс Диск подключается по OAuth-токену, остальные облака — через Client ID и Client Secret. Пошаговые инструкции: [CLOUDS.md](CLOUDS.md).

### Резервное копирование

Бэкапы базы данных создаются автоматически каждые 24 часа и хранятся в томе данных. Вы также можете вручную создать и скачать свежий дамп в разделе «Система».

Восстановление из дампа:

```bash
cd ~/player
RESTORE_CONFIRM=YES ./restore.sh /путь/к/файлу.dump
```

### Перенос на другой сервер

1. На старом сервере создайте архив переноса:

```bash
cd ~/player
./export-server.sh
# Если нужно упаковать и папку с музыкой:
# INCLUDE_MUSIC=YES ./export-server.sh
```

2. Скопируйте созданный архив `resonyr-transfer-*.tar.gz` на новый сервер.
3. На новом сервере клонируйте проект и запустите импорт:

```bash
git clone https://github.com/F0rest1er/ResonyrPlayer.git ~/player
cd ~/player
./import-server.sh /путь/к/resonyr-transfer-*.tar.gz
```

## Управление через Docker Compose

```bash
cd ~/player

# Просмотр статуса контейнеров
docker compose ps

# Логи приложения
docker compose logs -f --tail=100 app

# Перезапуск сервисов
docker compose restart

# Остановка
docker compose down
```
